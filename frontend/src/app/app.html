ผังโครงสร้างฐานข้อมูล (ER Diagram)

แบบจำลองข้อมูลเชิงสัมพันธ์ (Relational Data Model) ออกแบบผ่านแพลตฟอร์ม ERDPlus ตามสัญลักษณ์ Chen Notation แสดงความสัมพันธ์แบบ 1:N ระหว่าง Customer และ Order

เปิดไฟล์ภาพ SVG เต็มจอ OpenAPI JSON

ตาราง Customer (ลูกค้า)

จัดเก็บข้อมูลส่วนตัว ที่อยู่ และพิกัดภูมิศาสตร์ของลูกค้า

คอลัมน์ ชนิดข้อมูล ข้อจำกัด
id INTEGER Primary Key, Auto-increment
first_name TEXT NOT NULL (ชื่อ)
last_name TEXT NOT NULL (นามสกุล)
phone TEXT เบอร์โทรศัพท์
email TEXT อีเมล
address TEXT ที่อยู่
latitude REAL NOT NULL (พิกัดละติจูด)
longitude REAL NOT NULL (พิกัดลองจิจูด)
created_at DATETIME DEFAULT CURRENT_TIMESTAMP

ตาราง Order (รายการสั่งซื้อ)

จัดเก็บรายการสั่งซื้อ จำนวนกล่อง ราคา ยอดรวม และพิกัดจุดส่งของ

คอลัมน์ ชนิดข้อมูล ข้อจำกัด
id INTEGER Primary Key, Auto-increment
order_code TEXT UNIQUE, NOT NULL
customer_id INTEGER Foreign Key -> Customer(id) ON DELETE CASCADE
box_count INTEGER NOT NULL, CHECK (box_count >= 1)
price_per_box REAL NOT NULL (ราคาต่อกล่อง)
total_price REAL NOT NULL (ยอดรวมคำนวณ)
delivery_latitude REAL NOT NULL (พิกัดจุดส่ง)
delivery_longitude REAL NOT NULL (พิกัดจุดส่ง)
status TEXT DEFAULT 'Pending'
notes TEXT หมายเหตุการจัดส่ง
order_date DATETIME DEFAULT CURRENT_TIMESTAMP

ความสัมพันธ์ระหว่างข้อมูล (Relationship)

Customer (1) ——< places >—— Order (N)

  • Cardinality: แบบ One-to-Many (1:N)
  • ลูกค้า 1 คน สามารถมีประวัติการสั่งซื้อได้ตั้งแต่ 0 ถึงหลายรายการ (Optional Many)
  • คำสั่งซื้อ 1 รายการ ต้องผูกโยงกับลูกค้า 1 คนเสมอ (Mandatory One)
  • เมื่อลบข้อมูลลูกค้า รายการสั่งซื้อของลูกค้านั้นจะถูกลบตามโดยอัตโนมัติ (CASCADE) เพื่อความสมบูรณ์ของฐานข้อมูล (Referential Integrity)
