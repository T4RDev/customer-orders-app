1. แบบจำลองข้อมูล (ER Diagram - Chen Notation) ออกแบบจาก ERDPlus

แบบจำลองข้อมูลได้รับการออกแบบตามมาตรฐาน Chen Notation (Peter Chen ER Model) บนเว็บไซต์ https://erdplus.com/ เพื่อรองรับการจัดเก็บข้อมูลลูกค้าและรายการสั่งซื้อ โครงสร้างประกอบด้วย เอนทิตี (สี่เหลี่ยมสีแดง) คือ CUSTOMER และ ORDER, ความสัมพันธ์ (สี่เหลี่ยมข้าวหลามตัดสีม่วง) คือ Places แบบ 1 ต่อ กลุ่ม (1:N), และ คุณลักษณะ (วงรีสีฟ้า) โดยมี id เป็น Primary Key (ขีดเส้นใต้) และมีคุณลักษณะ distance_km (ระยะทาง KM)

1.2 พจนานุกรมข้อมูล (Data Dictionary)

ตาราง (Table) ฟิลด์ (Field) ชนิดข้อมูล (Type) Key / Constraint คำอธิบาย
customers
(ข้อมูลลูกค้า)		 id INTEGER PRIMARY KEY รหัสประจำตัวลูกค้า (Auto Increment)
first_name, last_name TEXT NOT NULL ชื่อ และ นามสกุลของลูกค้า
phone, email TEXT NULL เบอร์โทรศัพท์ และอีเมลสำหรับติดต่อ
address TEXT NULL ที่อยู่ปัจจุบันของลูกค้า
latitude, longitude REAL NOT NULL พิกัดทางภูมิศาสตร์ของลูกค้า (ใช้คำนวณระยะ 1 กม.)
created_at DATETIME DEFAULT CURRENT_TIMESTAMP วันเวลาที่บันทึกลูกค้าเข้าระบบ
orders
(รายการสั่งซื้อ)		 id INTEGER PRIMARY KEY รหัสลำดับคำสั่งซื้อ (Auto Increment)
order_code TEXT UNIQUE, NOT NULL รหัสคำสั่งซื้อ (เช่น ORD-20261003-8821-01)
customer_id INTEGER FOREIGN KEY อ้างอิงถึง customers.id (ON DELETE CASCADE)
box_count INTEGER NOT NULL (>= 1) จำนวนกล่องที่สั่งซื้อในออร์เดอร์นั้น
price_per_box, total_price REAL NOT NULL ราคาต่อกล่อง และราคารวมคำนวณอัตโนมัติ
delivery_latitude, delivery_longitude REAL NOT NULL พิกัดจุดจัดส่งสินค้า (ใช้คำนวณระยะ 2 กม.)
status, order_date TEXT / DATETIME DEFAULT สถานะการจัดส่ง และวันเวลาที่สั่งซื้อ
คำอธิบายความสัมพันธ์ (Cardinality): ลูกค้า 1 คน สามารถมีรายการสั่งซื้อได้ตั้งแต่ 0 รายการ จนถึงหลายรายการ (1:N) ในขณะที่คำสั่งซื้อแต่ละรายการจะต้องระบุลูกค้าผู้สั่งอย่างชัดเจน 1 คนเสมอ (Mandatory 1) และเมื่อลบลูกค้า ข้อมูลคำสั่งซื้อของลูกค้ารายนั้นจะถูกลบตาม (CASCADE)

2. คู่มือการใช้งาน Web API (API Documentation)

ระบบให้บริการผ่านสถาปัตยกรรม RESTful API พัฒนาด้วย NodeJS และ TypeScript โดยส่งและรับข้อมูลในรูปแบบ application/json สามารถทดสอบผ่าน Swagger UI ได้ที่ URL: http://localhost:3000/api/docs

2.1 สรุปภาพรวมเส้นทาง API ทั้งหมด

Method Endpoint URL หัวข้อตามโจทย์ หน้าที่การทำงาน
GET /api/customers 2.1 จัดการลูกค้า แสดงข้อมูลลูกค้าทุกคนในระบบ พร้อมจำนวนออร์เดอร์
POST /api/customers 2.1 จัดการลูกค้า เพิ่มข้อมูลลูกค้าใหม่ (ชื่อ, นามสกุล, พิกัด)
PUT /api/customers/:id 2.1 จัดการลูกค้า แก้ไขข้อมูลลูกค้าตาม ID
DELETE /api/customers/:id 2.1 จัดการลูกค้า ลบข้อมูลลูกค้าตาม ID
GET /api/customers/search 2.2 ค้นหาชื่อ/นามสกุล ค้นหาจากส่วนหนึ่งของชื่อ หรือ นามสกุล (Partial match)
GET /api/customers/nearby 2.3 ค้นหาระยะ 1 กม. ค้นหาลูกค้าทั้งหมดในรัศมี 1 กิโลเมตร จากพิกัดที่กำหนด
POST /api/orders/seed 3.1 จำลองออร์เดอร์ จำลองรายการสั่งซื้อ 20-30 รายการ ข้อมูลครบถ้วน
GET /api/orders 3.1 แสดงออร์เดอร์ แสดงรายการสั่งซื้อทั้งหมด พร้อมข้อมูลลูกค้าที่สั่ง
POST /api/orders 3.1.3 เพิ่มออร์เดอร์ สร้างคำสั่งซื้อใหม่
PATCH /api/orders/:id/box-count 3.1.3 แก้ไขจำนวนกล่อง แก้ไขเฉพาะจำนวนกล่องในแต่ละออร์เดอร์โดยตรง
DELETE /api/orders/:id 3.1.3 ลบออร์เดอร์ ลบรายการคำสั่งซื้อตาม ID
DELETE /api/orders/clear 3.2 ล้างข้อมูลทั้งหมด ล้าง (ลบทั้งหมด) รายการสั่งซื้อที่จำลองทั้งหมด
GET /api/orders/nearby 3.3 ค้นหาระยะ 2 กม. แสดงรายการสั่งซื้อทั้งหมดในระยะ 2 กิโลเมตร จากพิกัดที่กำหนด

3.1 จำลองรายการสั่งซื้อ 20-30 รายการ และจัดการจำนวนกล่อง

3.1 จำลองข้อมูล (Seed Orders): POST /api/orders/seed?count=25

curl -X POST "http://localhost:3000/api/orders/seed?count=25"

3.1.3 แก้ไขจำนวนกล่อง (Update Box Count): PATCH /api/orders/1/box-count

curl -X PATCH "http://localhost:3000/api/orders/1/box-count" \
  -H "Content-Type: application/json" \
  -d '{"box_count": 20}'

Response (200 OK):

{
  "success": true,
  "message": "Order #1 box count updated to 20",

สูตรการคำนวณระยะทาง Haversine Formula:
การคำนวณใช้รัศมีเฉลี่ยโลก $R = 6,371\text{ km}$ แปลงพิกัด Degrees เป็น Radians แล้วคำนวณ Great-circle distance ทำให้ได้ผลลัพธ์ระยะทางที่แม่นยำสูงทั้งในระยะ 1 กิโลเมตร และ 2 กิโลเมตร
